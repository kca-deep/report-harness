# 보고서 하네스 스킬 설계 — report-pipeline + report-research

- 날짜: 2026-07-21
- 상태: 설계 확정 대기 (사용자 검토 중)
- 결정 이력: 백지 설계 / 2게이트(목차→초안) / 2층 복리축적(즉시기록+규칙승격) / A안+셀프감사 서브에이전트 / claudian 완전 선택적 결합(코어 독립 동작, vault는 개인 확장) / 변환 툴체인 자체 내장(레거시 스크립트 소실 → 05_qa_report.md 명세 기반 재구축) / **플러그인 배포**(humanize-korean 번들 포함, 양식·계층 규칙은 신규 작성) / **양식 프로파일은 사용자 제공 양식에서 자동 추출**

## 1. 목적 — 최종 판정 기준

AI 대화로 외부자료를 조사하거나 제공자료 품질을 개선(사용자 피드백 루프)하여, **기관보고서 양식(형태·톤앤매너·조사·맺음말·개조식)으로 기본사항은 수정할 게 없는 품질의 hwpx**를 export하는 하네스. 배포 가능한 스킬 2종으로 구현한다.

3대 요구와 대응 설계:

| 요구 | 대응 |
|---|---|
| ① 기관보고서 양식 완성도 (수정 불필요 수준) | style-guide 성문화 + 게이트② 제시 **전** 스타일 셀프감사 + hwpx 직전 회귀검사 |
| ② md→hwpx 변환 실패 문제 (최대 페인포인트) | 변환 가능 md 프로파일 + prep 정규화 + 템플릿 병합 + **왕복 교차대조 QA** 툴체인 내장 (§6) |
| ③ 총괄표를 스토리텔링에 맞게 객관적으로 생성 | 게이트①에서 표 설계 승인 + 셀 단위 근거 추적 + hwpx-safe 표 프로파일 (§7) |
| ④ 기관 양식의 줄바꿈·폰트사이즈·계층 스타일 준수 | 사용자 제공 양식 hwpx를 분석해 **양식 프로파일(format-profile) 자동 추출** → 변환·검증에 적용 (§6-0) |
| ⑤ 계층별 서술형 문장의 AI 작성 표본 제거 | 번들된 **humanize-korean** 스킬을 게이트② 제시 전 윤문 단계로 편입 (§5) |
| ⑥ 플러그인 형태 배포 | report-pipeline + report-research + humanize-korean(에이전트 포함)을 하나의 Claude Code 플러그인으로 패키징 (§12) |
| ⑦ 근거 이미지의 보고서 차용 (1페이지의 1/3 이내) | 조사 단계 이미지 수집·출처 추적 + 게이트①에서 배치 승인 + 규격 검증 후 주입 (§7-1) |
| ⑧ 도식화는 SVG 대신 표 양식 Pool에서 선택 | `form/양식(표)/2. 도식 Pool.hwpx`(2단~5단 패턴+선택 기준)를 카탈로그화 — LLM이 논리전개 구조로 패턴 판정 후 작성란 슬롯에 내용 주입 (§7-3) |
| ⑨ 기본 틀·실보고서 관례의 하네스 주입 | `form/` 기본 양식 → format-profile.kca.md 시드, 실보고서 36건 코퍼스 분석 → style-guide.md 성문화 (§5·§6-0) |

핵심 원칙:

1. **hwpx는 게이트 통과 후 1회만 변환.** 피드백은 마크다운 단계에서 전부 소화 (과거 redraft v6·hwpx 5회 재빌드 사태 재발 방지).
2. **복리축적**: 피드백 즉시기록(lessons) → 회고 시 규칙승격(rules) → 다음 건 프리플라이트·회귀검사에 자동 적용. 변환 실패 패턴도 동일 경로로 축적.
3. **claudian 독립**: 코어는 설정 0으로 완결 동작. vault는 설정 시에만 켜지는 개인 확장.

## 4. report-research 스킬

조사 산출물의 1차 저장소는 **건 작업폴더 `research/`** — vault 없이 근거 추적이 완결된다.

- **모드 I (제공자료 적재)**: 드래그·지정 파일을 `research/provided/`에 복사(원본 불변). hwp·hwpx·pdf·docx는 kordoc(`parse_document`, 표는 `parse_table`)으로 파싱해 `{원본명}.md` 병치. md·txt는 파싱 생략.
- **모드 Q (사전지식 조회)** — `knowledge_vault` 설정 시에만: vault 위키 인덱스·페이지 검색, 인용 형식 `(출처: [[페이지명]] ← 원출처 URL/경로)`. 원출처 추적 가능하면 `[확정]`, 위키에만 있으면 `[미확정]`. 미설정 시 존재하지 않는 것처럼 생략.
- **모드 R (신규조사)**: 주제를 상호 독립 단위로 분해, 2개 이상이면 한 메시지 Agent 병렬 팬아웃(각자 다른 `fetched/{단위}/` → 병렬 쓰기 안전). 핵심 주장은 독립 출처 ≥2 교차검증. 산출물마다 출처 프론트매터(url·title·fetched_at·tool) + `_manifest.jsonl` append. 확정/추정 태깅 필수.
- **이미지 수집**: 조사 중 보고서의 근거·기초가 될 수 있는 이미지(공식 통계 차트·구조도·공표 도표 등)를 `fetched/{단위}/images/`에 원본 저장 + `_manifest.jsonl`에 출처(url·발행기관·수집일) 기록. 출처 불명 이미지는 수집하지 않는다. 차용 여부·배치는 pipeline의 게이트①에서 결정(§7-1) — research는 후보 수집까지만.
- **도구 선택** (tool-playbook.md): 법령·판례 → korean-law / 공시·재무 → opendart / 한글 문서 → kordoc / 차단 사이트 → insane-search / 다출처 심층 → deep-research / 일반 → WebSearch·WebFetch. **환경에 없는 MCP·스킬은 해당 행을 건너뛰고 일반 도구로 대체** (배포 환경 편차 흡수).
- **vault 브릿지 (선택)** — vault 설정 시: 조사 완료 후 `fetched/` 산출물을 vault `acquired/fetched/{주제슬러그}/`에 사본 적재 + vault 장부에 `[RESEARCH-PENDING]` 기록. `raw/`는 절대 수정 금지. 다음 건 모드 Q 재사용으로 이어지는 지식 복리 고리.
- **소스 우선순위**: 제공자료(I) → 사전지식(Q, 있으면) → 신규조사(R). 이미 있는 근거를 다시 조사하지 않는다.

## 5. 기관보고서 양식 — style-guide.md 성문화 범위

"기본사항 수정 불필요" 판정을 감사 가능하게 만들기 위해 성문화한다. **성문화 완료**: `references/style-guide.md` — `form/보고서/` 실보고서 34건 전수 분석(2026-07-22, 병렬 3차 교차 대조)으로 [철칙]/[관례]/[조건] 3등급 규칙화. 핵심:

- **형태**: 제목(명사구+유형 접미, (안)/(가칭)) + 발신 줄 `< '26. 3. 31.(화), 본부 팀 >`, □(절 전용)→ㅇ→-→※→＊ 위계, ㅇ 괄호 리드("(목 적)" 2음절 벌려쓰기), 붙임 3열 배너 표
- **서술량**: 한 항목=한 문장=2줄 이내(ㅇ 60~120자, - 40~90자), 초과분은 ※/＊/-/표로 배출, 나열 3개+속성 2개↑ → 표 전환
- **문체·종결**: **동작명사 종결**(~구축·~추진·~마련)이 표준 — "~함/~임"은 본문 금지(RFP·회의록만 예외. 기본 양식 통념과 달리 실코퍼스에서 확인된 규칙), 서술형(~합니다/~한다) 금지
- **조사·표기**: 조사 생략+가운뎃점 병렬, 아포스트로피 날짜(`'25. 6. 27(금)`), 백만원/천원 축약, 산식 병기, 원어 병기+＊각주
- **톤앤매너**: 객관·건조체, 강조는 볼드 단일(핵심 명사구만 선별, 밀도는 문서 격 비례), 근거 문미 괄호("(5.19 기관장 지시사항)")
- **팩트 무결성**: 사실/주장 절 분리, 확정/추정/경계 태깅, 모든 수치에 출처
- **맺음말**: 계획형 "□ 향후 계획"+"할 일 : 시점" / 조사형 "□ 주요 시사점" 종결, 의례적 마무리 문구 금지

**스타일 셀프감사 (게이트② 제시 전)**: 초안 생성 직후 독립 서브에이전트(general-purpose 스폰, style-guide + rules `[초안]` 태그 주입)가 위 항목을 감사 → 위반 수정 후에야 사용자에게 제시. **사용자가 스타일 교정이 아니라 내용 검토에만 집중하게 만드는 장치.**

**AI 표본 제거 (스타일 감사 직후, 게이트② 제시 전)**: 번들된 humanize-korean 스킬로 계층별 서술형 문장의 AI 작성 표본(번역투·기계적 병렬·리듬 균일성 등)을 제거한다. humanize의 철칙(내용·사실·수치·인용 한 글자도 불변, 문체·리듬만 윤문)이 본 하네스의 팩트 무결성 원칙과 정합. 개조식 명사형 종결부는 윤문 대상에서 제외하고 서술형 구간(배경 설명·근거 서술 등)만 적용한다.

## 6. md→hwpx 변환 서브시스템 (최대 페인포인트 대응)

소실된 레거시 툴체인의 검증된 구조(260720건 05_qa_report.md 명세)를 스킬 내장 `scripts/`로 재구축한다.

**대원칙 — "작성된 md 그대로" 변환**: 게이트②에서 승인된 20_draft.md의 내용·구조·표·각주가 hwpx에 1:1로 재현되어야 한다. prep은 마크업 정규화만 하며 내용을 한 글자도 바꾸지 않는다(무손실). 왕복 교차대조가 이 원칙의 검증 장치다. 이 원칙을 성립시키기 위해 writer가 처음부터 변환 가능 프로파일로만 작성한다 — "변환기에 맞춰 나중에 고치는" 것이 아니라 "변환되는 것만 쓰는" 구조.

**0단계 — 양식 프로파일 자동 추출 (extract_format_profile.py + kordoc)**: 사용자가 기관 양식 hwpx를 제공하면(`template_hwpx` 설정 또는 대화 중 전달), kordoc `parse_metadata`·`parse_document`로 분석해 **줄바꿈 관례(계층별 문단 간격·들여쓰기), 폰트·사이즈(제목/본문/표/각주별), 계층형 구조 나열 기호와 단수, 표 스타일**을 `{state_dir}/format-profile.md`로 추출한다. 이 프로파일은 하드코딩이 아니라 **제공된 양식에서 도출된 rules**이며, 초안 작성(프리플라이트)·변환(build)·검증(validate) 세 지점에서 참조된다. 양식이 바뀌면 재추출로 갱신 — 기관별 프로파일 복수 보관 가능(`format-profile.{기관슬러그}.md`). 양식 미제공 시 kordoc 보고서 preset 기본값 사용. **KCA 프로파일은 `references/format-profile.kca.md`로 번들 시드 완료**(사용자 환경 기본값) — state_dir에 동명 프로파일이 있으면 그것이 우선.

4단 방어:

1. **작성 단계 예방 — md-profile.md**: writer는 처음부터 변환 가능 서브셋으로만 작성.
   - 허용: □/ㅇ/- 개조식 위계(최대 4단), GFM 표(셀 병합 없음, 초기 상한 6열 — lessons로 조정), ＊ 각주, 도해 마커
   - 금지: HTML 태그, 중첩 표, 셀 내 줄바꿈 남용, 변환기 미지원 특수문자 — 금지 목록은 lessons에서 계속 증보
2. **prep 정규화 — prep_report_md.py**: 승인된 20_draft.md → 40_prepared.md. HTML 주석 제거, 각주 정의 치환, 구분선 정리, 표 폭 지시자 처리, 개조식 위계↔스타일 매핑 정합화. (레거시에서 발견된 정규식 개행 삼킴 버그 등은 rules 시드로 반영)
3. **변환·병합 — kordoc MCP + build_hwpx.py**: 변환 자체는 스킬(모델)이 kordoc `generate_document`(preset=보고서, 명조, 15pt) MCP 호출로 수행하고, build_hwpx.py는 그 전후 처리(`template_hwpx` 설정 시 기관 레터헤드·계층 스타일 병합, 표 열 폭 내용 비례 재분배)를 담당. 스크립트는 stdlib-only — MCP를 직접 호출하지 않는다.
4. **검증 — validate_hwpx.py (왕복 교차대조)**:
   - 구조 검증: zip/xml 무결성, 스타일 id 연속성
   - **내용 왕복 대조**: 산출 hwpx를 kordoc `parse_document`로 되읽어 원본 md와 항목별 대조 (제목/발신정보/□ 섹션 수/ㅇ·- 위계 매핑/표 수·행·열/각주 수/수치 표본) → 40_qa.md 대조표 산출
   - 불일치 발견 시: 자동 수정 → 재변환 → 재검증 (최대 2회). 잔여 불일치는 사용자에게 명시 보고 — **조용한 변환 손실 금지**
   - 실패 패턴은 lessons.jsonl에 `gate:"convert"`로 기록 → 반복 시 md-profile 금지 목록·prep 규칙으로 승격 (**변환 문제도 복리 대상**)

md 최종본(20_draft.md)이 항상 SSOT — hwpx 변환이 끝내 실패해도 md를 인도하고 원인을 보고한다.

## 7. 총괄표 생성 (스토리텔링 정합 + 객관성)

- **설계는 게이트①에서 승인**: 10_outline.md에 "표 설계" 절 포함 — 어떤 총괄표가 어느 절에서 어떤 논지를 지탱하는지(예: 조사결과 총괄표 = 상세 사례를 한눈에 묶어 시사점 절의 근거가 됨), 열 구성과 행 단위를 명시. 표가 스토리텔링의 장식이 아니라 논지 구조물이 되도록 위치를 먼저 확정한다.
- **객관성 — 셀 단위 근거 추적**: 표의 모든 셀 값은 `research/` 산출물(제공자료·위키 인용·신규조사)에서만 추출. 추출 시 셀→출처 매핑을 표 하단 주석 또는 30_audit.md에 기록. 출처 없는 셀은 공란 + `[미확인]` 표기 — 추정치로 메우지 않는다. 확정/추정 혼재 표는 태깅 열 또는 각주로 구분.
- **집계의 객관성**: 합계·비율 등 파생값은 스크립트 계산 가능해야 하며(제3자 재계산 가능 원칙), 산식을 각주로 병기.
- **변환 안전**: 표는 md-profile의 표 규격(열 수 상한·병합 금지) 안에서 설계 — 게이트①에서 규격 초과 표는 분할안을 함께 제시.

## 7-1. 근거 이미지 차용 (1페이지의 1/3 이내)

외부조사에서 수집한 이미지 중 **보고서의 근거·기초가 되는 것만** 본문에 차용한다 — 장식용 이미지는 쓰지 않는다.

- **차용 기준**: ⓐ 본문 논지를 직접 지탱하는 근거(공식 통계 차트·제도 구조도 등)일 것, ⓑ 출처가 `_manifest.jsonl`에 실재할 것, ⓒ **규격이 1페이지의 1/3 이내**일 것 — A4 기준 본문 폭 170mm × 높이 상한 90mm. 초과 이미지는 축소해도 판독 가능하면 축소, 아니면 차용 포기하고 텍스트 요약 + 출처 각주로 대체.
- **배치 승인은 게이트①**: 10_outline.md에 "이미지 배치" 절 포함 — 어떤 이미지가 어느 절에서 어떤 논지의 근거인지, 규격 판정 결과와 함께 제시. 표 설계와 동일한 원칙: 이미지는 장식이 아니라 논지 구조물.
- **본문 표기**: md에는 이미지 마커(`도해: {id}` 형식)로 위치만 지정하고, 캡션에 출처(발행기관·자료명·연도)를 필수 병기. 저작권 유의 자료(유료·비공개)는 차용하지 않고 인용·요약으로 대체.
- **주입·검증 (변환 단계)**: `inject_image.py`가 마커 문단을 이미지로 치환(레거시 검증 방식 계승 — 주입 전 픽셀→mm 환산으로 규격 상한 검증, 주입 후 왕복 QA에서 이미지 존재·위치 확인). 규격 검증 실패 시 변환을 멈추고 보고.
- 팩트체크(§7-2) 범위에 이미지도 포함: 캡션 출처가 manifest와 일치하는지, 이미지 내용이 본문 주장과 정합하는지 확인.

## 7-3. 도식화 — SVG 금지, 표 기반 도식 Pool

레거시 파이프라인의 SVG 도해(diagram_D1.svg → PNG → 주입) 방식을 폐기하고, 기관 도식 Pool(`form/양식(표)/2. 도식 Pool.hwpx`, 2단~5단 정의서)의 **표 기반 도식**으로 대체한다.

- **선택**: LLM이 도식화할 내용의 논리전개 구조(도입 유무/전개 항목 수/결과 단복수/강조 대상)를 판정해 카탈로그(`references/diagram-pool.md`)의 판정표에서 패턴을 고른다. 복수 후보면 단순한 쪽 우선(가독성).
- **작성란 주입**: 선택한 패턴의 빈 셀(슬롯)에 들어갈 텍스트를 본문·근거에서 추출 — 명사구 위주 1~2행, 본문 문장 복붙 금지. 슬롯 내용도 팩트체크 대상.
- **md 표기**: 초안에는 `도식: {패턴ID}` 마커 + 슬롯 내용 목록으로 표기(md-profile 준수), 변환 단계에서 도식 Pool 원형 표(병합 포함)를 복제해 치환.
- **승인**: 게이트①의 "도식 설계" 절에서 패턴 선택·슬롯 내용을 승인받는다.
- 도식 Pool hwpx는 플러그인에 번들(§12) — 배포 환경에서도 동일 동작.

## 7-2. 팩트체크 (게이트② 승인 후, 변환 전)

확정된 초안을 대상으로 독립 서브에이전트가 **전수 사실 검증**을 수행한다 — 초안을 쓴 컨텍스트와 분리된 검증자가 "반박할 수 있는가"의 관점으로 본다:

- **추적 검증**: 초안의 모든 수치·인용·고유명사·날짜를 `research/` 산출물(제공자료·위키 인용·조사 결과)과 대조 — 출처가 실재하고 값이 일치하는가. 표 셀→출처 매핑(§7)도 이때 전수 확인.
- **태깅 정합**: `[확정]` 표기 항목이 실제로 검증 가능한 원출처를 갖는지 확인. 불충분하면 `[추정]`으로 강등 제안.
- **외부 재검증 (선택적)**: 근거가 research 산출물에 없거나 의심스러운 핵심 주장은 웹 재검색으로 교차확인 (핵심 주장 한정 — 전체 재조사가 아님).
- **산출**: `35_factcheck.md` — 항목별 판정표(일치/불일치/출처 없음). 불합격 항목이 있으면 수정 후 **게이트② 간이 재확인**을 거친다(사실이 바뀌면 사용자가 다시 봐야 함). 전 항목 합격 시에만 변환 단계로 진행.
- 팩트체크에서 발견된 오류 유형도 lessons.jsonl에 `gate:"factcheck"`로 기록 — 반복 시 초안 작성 규칙으로 승격.

## 8. report-pipeline — 3케이스 동선과 2게이트

        ↓ 승인
[프리플라이트] rules.md [목차][초안] + format-profile 로드 → md-profile 준수 초안 생성
        ↓
[스타일 셀프감사] 서브에이전트: style-guide+rules 감사 → 위반 수정 (§5)
        ↓
[AI 표본 제거] humanize-korean: 서술형 구간 윤문 (내용 불변, §5)
        ↓
[게이트②] 20_draft.md 제시 → 승인 대기
   ↑  피드백 → lessons.jsonl 즉시 append → 수정 → vN 재제시 (hwpx 절대 선행 금지)
        ↓ 승인

        ↓

## 9. 복리축적 2층

**층1 — lessons.jsonl (즉시기록)**: 게이트 피드백·변환 실패 수신 즉시 1줄 append:

```json
{"date":"2026-07-21","case":"260721_건명","gate":"outline|draft|factcheck|convert","feedback":"표가 페이지 넘어감","fix":"표 분할","promoted":false}
```

**층2 — rules.md (규칙승격)**: final 인도 후 회고에서 ⓐ 2회 이상 반복 또는 ⓑ 명백히 일반화 가능한 lessons만 승격 제안 → **사용자 승인 후** 기록, 해당 lesson `promoted:true` 마킹:

```markdown
- R007 [hwpx] 표는 한 페이지 안에 들어가게 분할한다 (근거: 260721건, 260728건)
- R008 [초안] 지적사례(사실)와 건의(주장)는 절을 분리한다 (근거: 260714건)
```

태그 `[목차]`/`[초안]`/`[hwpx]`가 적용 지점 지정. **적용 지점 2곳**: ① 프리플라이트(선반영 — 실수를 아예 안 함), ② 회귀검사(hwpx 직전 독립 감사 — 새어나간 위반 포착). rules.md 초기값은 빈 파일이 아니라 기존 실전 교훈(팩트/주장 분리, 확정/추정 태깅, prep 개행 버그류, 표 규격 등)을 R001~로 시드.

## 12. 플러그인 패키징·배포

최종 배포 형태는 **Claude Code 플러그인 1개** — 스킬을 개별 cp하는 대신 플러그인 설치로 일괄 배포한다.

- **구성**: `.claude-plugin/plugin.json` 매니페스트 + `skills/`(report-pipeline, report-research, humanize-korean) + `agents/`(humanize 계열 — ai-tell-detector, korean-style-rewriter, naturalness-reviewer 등 파이프라인이 실제 사용하는 것만 선별) + 번들 자산(도식 Pool hwpx — §7-3 표 원형 복제용, 기본 양식 hwp).
- **배포 제외 (기밀·PII 가드)**: `form/보고서/`(기관 내부 실보고서 — 실명·연락처·내부 계획 포함)와 `docs/analysis/`(실보고서 인용 포함)는 **플러그인 패키지·공개 레포에 절대 포함하지 않는다**. 스타일 지식은 이미 style-guide.md로 규칙화(탈맥락·비식별)됐으므로 원문 배포가 불필요. 배포 스크립트에 제외 목록을 하드코딩하고, 패키징 시 PII 스캔(전화·이메일 패턴)을 통과 조건으로 둔다.
- **humanize-korean 번들 방식**: 기존 `~/.claude/skills/humanize-korean`(및 관련 에이전트)을 레포로 **사본 동기화**해 플러그인에 포함. 원본의 업데이트를 주기적으로 반영(동기화 스크립트 또는 수동 cp — 구현 계획에서 확정). 플러그인 내 스킬 참조는 `plugin:skill` 네임스페이스 규약을 따른다.
- **의존성 고지**: kordoc MCP는 플러그인에 포함되지 않는 외부 의존 — README에 설치 안내를 명기하고, 미설치 환경에선 md 인도 + 안내 메시지로 강등 동작(§10). korean-law·opendart 등 조사용 MCP는 선택 의존(없으면 일반 도구 대체, §4).
- **버전·변경 관리**: plugin.json 버전 + CHANGELOG. rules·lessons 등 가변 상태는 플러그인 밖(`state_dir`)이므로 업그레이드에 안전.
- **개발 동선**: 레포에서 수정 → 로컬은 cp 재배포로 즉시 검증 → 배포 시점에 플러그인 버전 태깅.
