# md-profile — hwpx 1회 변환 보장 마크다운 서브셋

> 대상: `/report-draft`가 생성하는 `20_draft.md`(게이트②에서 사용자가 승인하는 최종 초안).
> **이 프로파일 안에서만 쓰면 hwpx 1회 변환이 보장된다.** GFM 전체가 아니라, kordoc 변환기가
> 손실 없이 재현할 수 있다고 검증된 부분집합만 허용한다 — "변환기에 맞춰 나중에 고치는" 것이
> 아니라 "변환되는 것만 처음부터 쓰는" 구조다(spec §6 대원칙). 위반 여부는 사람 눈이 아니라
> `scripts/lint_md_profile.py`(결정론 정규식, stdlib-only)가 기계 검출한다 — 초안 생성 직후·
> 수정 시마다 실행되는 shift-left 게이트다.
>
> 검출되지 않는 위반(스코프 아웃)은 §4에 별도 명시 — 그 몫은 스타일 감사(2차 방어)가 담당한다.

## 1. 허용 문법 전량

### 1-1. 개조식 위계 (최대 4단)

```
□ 1단 — 절 제목 전용 (본문 서술에 쓰지 않는다)
 ㅇ 2단 — 요지 (○도 허용, 문서 단위로 하나만 통일)
   - 3단 — 상세
※ 참조·단서 (4단, 문단 선두)
＊ 각주 (4단, 전각 ＊만 합법 — 아래 §2 정책 1 참조)
```

- 각 위계 기호는 **줄(항목) 선두**에서만 마크다운으로 해석된다. 정규식 `LEAD`가 인정하는 선두
  기호는 `□ ㅇ ○ - ※ ＊` 그리고 번호형 `1. `·`[1]`이다.
- 대시(`-`)는 **중첩 불가**다. 같은 ㅇ 블록 안에서 대시가 여러 번 나와도 전부 동일 들여쓰기여야
  하며, 더 들여쓴 하위 대시는 위반(`depth-exceeded`)이다. 4단으로 더 내려가야 하면 대시를
  늘리지 말고 ※(단서)나 ＊(각주)로 배출한다.
- 한 ㅇ 항목 아래 대시 나열은 5개까지 — 6번째부터 `bullet-overflow`.

### 1-2. 표 (GFM)

- 열 상한 **6열**(초기값 — lessons로 조정 가능). 셀 병합 없음.
- 캡션은 표 위 별도 줄: `[ 캡션 ]`(본문 개념도·집계·비교표) 또는 `< 캡션 >`(참고·근거 박스).
  둘 다 꺾쇠·대괄호 라벨이지 HTML 태그가 아니다 — `html-tag` 룰은 이 표기를 위반으로 잡지 않는다.
- 도식화가 필요하면 표를 직접 그리지 않고 `도식: {패턴ID}` 마커(§1-4)로 위임한다.

### 1-3. 인라인 강조

- **`**볼드**`가 유일한 인라인 마크업**이다. 이탤릭(`*..*`)·취소선(`~~..~~`)·인라인 코드(`` `..` ``)·
  헤딩(`#`)·인용(`>`)·서술 중 공백-하이픈(` - `)은 전부 금지.
- 핵심 명사구만 선별 볼드 — 문장 전체 볼드는 스타일 감사(2차 방어) 소관이며 린트는 검출하지 않는다.

### 1-4. 도식 마커

- 표로 그릴 도식은 `도식: {패턴ID}` + 슬롯 내용 목록으로 표기한다(`diagram-pool.md` 판정표에서
  패턴 선택). 변환 단계(`hwpx-recipe.md`)에서 도식 Pool 원형 표로 치환된다 — md 단계에서는
  실제 표를 그리지 않는다.

### 1-5. 이미지 마커

- `도해: {id}` 형식으로 위치만 지정하고, 캡션에 출처(발행기관·자료명·연도)를 병기한다. 실제
  이미지 주입은 변환 단계에서 규격 판정(`check_image_size.py`) 통과분만 이뤄진다.

## 2. 리뷰 확정 정책 (구현 승인 사항)

이 절은 브리프의 6개 룰 표(§3)로 다 담기지 않는, 리뷰에서 별도로 확정된 세부 규칙이다.

1. **각주 선두는 전각 ＊만 합법.** 반각 `*` 선두는 위반이다. `LEAD` 정규식이 반각 `*`를 항목
   선두 허용 기호에서 제외해 두었으므로, 선두 반각 `*`는 볼드 마커로 오인되지 않고
   `inline-markdown`/`non-bold-markup`로 잡힌다. `prep_report_md.py`가 각주 이스케이프
   `\* ` → `＊ `를 정규화하지만, 초안 단계에서부터 ＊만 쓴다.
2. **" - "(공백-하이픈) 서술 중 사용 금지.** 기간·범위 표현은 물결(`~`)을 쓴다 —
   `'26. 1. 13(화) ~ 1. 23(금)`. `INLINE_BAD` 정규식이 서술 중 공백-하이픈을 `inline-markdown`
   위반으로 잡는다(항목 선두의 대시는 별도 취급이라 영향 없음).
3. **HTML 주석은 한 줄로만.** `<!-- ... -->`가 같은 줄에서 열리고 닫혀야 한다. 여는 `<!--`와
   닫는 `-->`가 다른 줄에 걸치는 다중행 주석은 `prep_report_md.py`가 `PrepError
   (multiline-comment)`로 **거부**한다(exit 2) — 린트가 아니라 prep 단계 하드 실패다. 산문
   서술 중에 `-->`를 문자 그대로 쓰지 않는다(주석 종료 마커로 오인될 수 있음).
4. **대시는 중첩 불가 — 4단은 ※/＊로.** §1-1과 동일 규칙의 재확인: 동일 ㅇ 블록 내 대시는
   전부 동일 들여쓰기여야 한다(들여쓰기 폭 자체는 자유, 단 블록 내에서 일관). 더 깊은 단계가
   필요하면 대시를 늘리지 말고 ※(단서)나 ＊(각주)로 배출한다.
5. **꺾쇠 라벨은 합법, 실제 HTML 태그만 위반.** `<AI 활용 방안>`, `<A 등급>` 같은 코퍼스 관례
   라벨은 통과한다. `html-tag` 룰은 실제 태그명 화이트리스트
   (`br div span table thead tbody tr td th img em strong hr ul ol li sub sup font center h1~h6`)에
   매치하는 `<태그 ...>` 형태만 잡는다 — 임의의 꺾쇠 텍스트를 전부 태그로 오인하지 않는다.
6. **※ 인라인 후행 참조는 합법.** "… ※ 상세는 붙임 2"처럼 문장 뒤에 붙는 ※는 코퍼스 합법
   관례이므로 `misplaced-marker`가 검출하지 않는다(□만 문장 중간 위치를 검출 대상으로 삼는다 —
   §3 표 참조).

## 3. 금지 목록 — 린트 룰 7종

`lint_md_profile.py`가 검출하는 룰은 7종이다(브리프 초안 6종 + 구현 중 실제 발견되어 추가된
`misplaced-marker`). 표의 예시는 그대로 `lint_text()`에 입력하면 재현되는 최소 사례다.

| 룰 ID | 검출 대상 | 위반 예시 | 수정 예시 |
|---|---|---|---|
| `inline-markdown` | 서술 중 공백-하이픈· 반각 `*`(볼드 아님)·백틱·`#`헤딩·` > `인용 | `ㅇ 조사 결과 - 세 가지로 요약됨` | `ㅇ 조사 결과는 세 가지로 요약됨` |
| `non-bold-markup` | `**볼드**` 이외의 인라인 마크업(이탤릭 `*..*`, 취소선 `~~..~~`, `***`삼중별) | `ㅇ 이는 *매우 중요*한 사안임` (단일 * 는 inline-markdown 도 동시 트리거됨) | `ㅇ 이는 **매우 중요**한 사안임` |
| `table-too-wide` | 표 열 수 7열 이상 | \`| a | b | c | d | e | f | g |\` | 열을 6개 이하로 분할하거나 행 전환으로 재구성 |
| `depth-exceeded` | 대시가 같은 블록 내 기준선보다 더 들여써져 중첩됨 | `ㅇ 요지\n  - 상세\n    - 중첩 세부` | `ㅇ 요지\n  - 상세\n※ 중첩 대신 단서로 배출` |
| `bullet-overflow` | 한 ㅇ 아래 동일 레벨 대시 6개째 등장 | `- 상세1`~`- 상세6`(6개 연속) | 5개 이하로 압축하거나 하위 ㅇ로 절 분리 |
| `html-tag` | 실제 HTML 태그 화이트리스트 매치 (꺾쇠 라벨 `<AI 활용 방안>`은 제외) | `ㅇ 내용 <br> 줄바꿈` | `ㅇ 내용은 줄을 바꿔 서술` |
| `misplaced-marker` | 항목 선두가 아닌 위치의 □(문장 중간 재등장 포함) | `ㅇ 문장 중간에 □ 표기가 있는 경우` | `ㅇ 문장 중간에 표기가 있는 경우` |

## 4. 스코프 아웃 (린트 미검출 — 스타일 감사가 2차 방어)

정규식 결정론 검출의 오탐 위험 때문에 의도적으로 범위 밖에 둔 패턴이다. 이 패턴들은
`lint_md_profile.py`가 통과시키므로, `/report-draft`의 **스타일 셀프감사**(독립 서브에이전트,
style-guide 기준)가 잡아야 한다.

- **ㅇ-only 깊은 중첩**: ㅇ(또는 ○) 자체의 들여쓰기 단계가 과도하게 깊어지는 패턴. 대시와 달리
  ㅇ은 절 경계 리셋 신호로 쓰이기 때문에(§ `lint_md_profile.py` `bullet_run = 0` 처리) 정규식만
  으로 깊이를 판정하면 오탐이 많아 이번 범위에서 제외했다.
  (`test_lint_md_profile.py::test_bullet_run_resets_at_section` 참조)
- **○·ㅇ·＊이 문장 중간에 등장**하는 패턴. □는 문장 중간 재등장을 `misplaced-marker`로 잡지만
  (`test_second_box_on_valid_line_detected`), ○/ㅇ/＊은 본문에서 정상적으로 등장할 수 있는
  문맥이 많아(예: "＊ 표시 항목은…") 결정론 검출 대상에서 뺐다.

이 목록에 새 위반 유형이 코퍼스에서 반복 관찰되면 §5 절차로 룰을 승격한다.

## 5. lessons 증보 절차

1. **위반 유형 발견**: 게이트② 피드백, 팩트체크, 왕복 QA(hwpx 되읽기 텍스트 재검사, §3의
   `AI 티 결정론 방지 3중 장치 ③`) 어디서든 md-profile을 벗어난 잔재가 나오면 즉시
   `lessons.jsonl`에 1줄 append(`gate` 태그: `outline|draft|factcheck|convert`, 단계 마무리
   태그: `[draft]`/`[export]`).
2. **반복 관찰(동일 유형 2회 이상)**은 회고까지 기다리지 않고 그 자리에서 승격 후보로 제안 —
   사용자 승인 시 `rules.md`에 `R0NN [draft]` 형태로 즉시 반영한다.
3. **룰 추가**: 일반화 가능한 위반은 이 문서(§2 또는 §3)에 항목을 추가하고, 대응하는 정규식/
   조건을 `lint_md_profile.py`의 `LEAD`/`INLINE_BAD`/`NON_BOLD`/`HTML`/`TABLE` 등에 반영한다.
   룰 ID를 새로 만드는 경우 `tests/test_references_consistency.py`의 `RULES` 목록과
   `tests/test_lint_md_profile.py`에 회귀 테스트를 함께 추가한다 — 문서·테스트·구현 3자가
   항상 1:1 정합이어야 한다(이 파일 자체가 그 정합성의 검증 대상이다).
4. **린트 스크립트 갱신 후**에는 `python3 -m pytest tests/test_lint_md_profile.py
   tests/test_references_consistency.py -v`로 회귀를 확인하고 나서 rules.md 승격을 완료한다.
